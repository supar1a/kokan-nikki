# 短冊

仲間うちだけで、縦書きで、本音や雑記を書き散らせる場所。

- **返事はいらない。** 誰かに宛てて書くのでも、応えるのでもない。
- **順番も手番もない。** 誰でも、いつでも書ける。
- **整っていなくていい。** エッセイである必要も、日記である必要もない。
- **いいね・既読・閲覧数・フォロワー数は、一つも作らない。** 数えないことが、この場の性格そのもの。
- **日記ほど私的すぎず、SNSほど公的すぎない。** 濃い文脈が共有されている前提で書ける。
- **縦書きで「読む」。** タイムラインを眺めるのではなく、文章を読む。

書く画面では **⌘（Windows は Ctrl）+ Enter** で投稿できる（画面には出していない）。
変換中は決して送らない（Enter は変換の確定にも使うので）。

**かな漢字変換中の下線は、縦組みでも文字の左に出る。** 日本語の組版では
傍線は右だが、あの下線は CSS の `text-decoration` ではなく、ブラウザが
変換中の文字に直に描いているもので、`text-underline-position` は届かない。
消すには入力欄そのものを隠して全部こちらで描くしかなく、そうすると
**どの文節を変換しているのかが見えなくなる**。日本語を打つうえでそちらの
損のほうが大きいので、直していない。確定すれば消える。

**写真は貼り付けで一枚だけ。** ファイル選択も引きずり込みも無い。
貼ると、**書いていたところで本文が二つに割れて、そこに写真そのものが挟まる**。
印や添え書きではなく、出るときと同じ姿がその場に置かれる。外すとまた一つにつながる。

## 二つの見え方

グループには、**目次**と**巻物**がある。見出しの「巻物で読む／目次で見る」で行き来する。

### 目次（既定）

小説の目次のように、**一篇が一行（一列）**。題が上、書いた人と日付が下に落ちる。
グループの名前が、本の題のように右端に大きく置かれる。

**押すと、別の画面へ飛ばずにその場で開く。** 縦組みなので、開いた分だけ左へ伸びる。
読みたい一篇だけが、そこで巻物になる。もう一度押せば畳まれる。

- 見出しは列の上、名前と日付は列の下。そのままでは同じ一篇だと結びつかないので、
  **点線のリーダーで繋いで**、ひと続きの一行として読めるようにしている（小説の目次と同じ）。
- 折り畳みは `<details>` に任せている。状態を持たずに済み、キーボードでも開ける。
- 畳んでいるあいだ、写真は**取りにいかない**（`loading="lazy"` が効く）。
- **題は付けなくてよい。** 無ければ本文の一行目を借りる（一文で切る）。
  借りものの見出しは、開いたら隠す。同じ一行を二度読ませないため。

### 巻物

全員の短冊が**全文のまま、右から左へ連なっている**。
開いた瞬間に、もう誰かの文章を読んでいる状態になる。

**並びは古いものから新しいものへ。** 縦組みでは、それが右から左へ流れる向きになる。
一枚の中で後の文字ほど左にあるのと、向きが揃う（巻物も右端から書き始める）。
最新を右端に置くと、縮尺を変えたときに時間が逆流するうえ、
新着を読むとき必ず逆時系列になってしまう。

**ひらいたときは、いつも左端（いちばん新しいところ）に立つ。** PC でもスマホでも同じ。
読みかけの位置に着地させると、ひらくたびに違う場所から始まって落ち着かない。
どこまで読んだかは、巻物の中の細い朱の目印が受け持つ。

- カードも、抜粋も、「続きを読む」もない。**走り読みという行為が成立しないようにしてある。**
- **投稿と投稿のあいだに罫は引かない。** 段落は日本語の縦組みどおり「一字下げ＋改行」だけで
  詰めてあるので、そのぶん余る空きが、そのまま投稿の切れ目として働く。
  仕切っているのは、書いた人の名前と、空きだけ。
- ただし**グループの一覧は囲う**。あちらは「読むもの」ではなく「選ぶもの」なので、
  一つひとつに輪郭がいる。
- 本文はリンクではない。読むもの、引用するものなので。
- リンクなのは**書いた人の名前**（その人の分だけを続けて読む）と**日付**（その一枚だけを開く）。
  日付は、触る前から線を出して戸口だと分かるようにしてある（手で触る画面には hover が無いので）。
- 自分の書いたものには **「じぶん」** が付く。ひらけば、編集も削除もそこにある。
- 前に見たあとに書かれた分の手前に、細い朱の目印が入る。**未読の「数」はどこにも出さない。**
  数が出た時点で、消化すべきものになってしまうので。

## 言葉づかい

機能の名前は、ウェブで通じている言葉をそのまま使う（投稿・下書き・公開・編集・削除・メンバー・ログアウト）。
雰囲気は、本文と佇まいの側で出す。

聞くことも最小にした。グループを作るときに要るのは**グループ名と自分の名前だけ**。
ひとことも合言葉も置いていない。

合言葉はいちど作ったが、外した。あれは URL の「追加の鍵」ではなく、
**同じ強さの二本目の鍵**だった。どちらか一方が漏れれば入られるので、
持たないほうが出回る秘密が少なくなる。

## 動かす

```sh
brew install postgresql@17                                   # まだ無ければ
pg_ctl -D /opt/homebrew/var/postgresql@17 start              # 起こす
createdb kokan_nikki

npm install
cp .env.example .env        # DATABASE_URL を埋める
npx prisma migrate dev
npm run seed                # 手ざわりを見るための種データ（任意）
npm run dev
```

### 開発中の人の切り替え

入口の下に「開発用」の貼り紙が出る。人の釦を押せばその人として見られる。
本番ビルドでは出ないし、その処理も中身ごと消えて `throw` だけが残る。

種データを入れると、はなこで見たときに未読の目印が出る状態から始まる。
グループ「三人のところ」の招待 URL は `/b/sannin`。

## 名乗り

**アカウントはない。** 調整さんや walica と同じで、登録もログインもない。

- はじめて来た人は、**グループを作るところから始まる**。聞くのは、グループ名と自分の名前だけ。
  名前だけ先に決めても、まだ何も無い画面に出るだけなので、そこは通らせない。
- 名前は**ブラウザのクッキー**に紐づく。サーバー側には名前しか持たない。
- 誰かを誘うときは、**グループの URL をそのまま渡す**。開いた人は名前を入れて、そのまま仲間になる。
  鍵はこの URL 一本きり（31 種 × 14 字 ≒ 2^69 通り）。

### クッキーを失ったら

グループの URL をひらくと、メンバーの名前が並ぶ。そこから自分を選び直せば戻れる。

**つまり、URL を持っている人は誰にでもなりすませる。** 照合するものが何もないので、
これは防げないし、防ごうとしていない。守っているのは「その URL を知っているのは
仲間だけ」という一点だけ。仲間うちで使う前提の割り切り。

せめて、すでに名乗っている人にはこの選び直しを出さない（まだ誰でもない人の戻り道に留める）。

## 画面

| 道筋 | なに |
|---|---|
| `/` | はじめての人にはグループを作ってもらう。名乗っていればグループの一覧 |
| `/new` | グループを作る |
| `/me` | 名前を変える・このブラウザから消す |
| `/b/[slug]` | 目次。`?view=maki` で巻物。**この URL が招待状**。まだ仲間でない人には名前をきく |
| `/b/[slug]/write` | 書く |
| `/b/[slug]/by/[userId]` | その人の分だけを続けて読む |
| `/b/[slug]/members` | メンバーと招待 URL |
| `/s/[id]` | 一枚だけを開く |
| `/s/[id]/edit` | 編集 |

## 見えかた

| | URL を知らない人 | URL を知っている人 | メンバー | 書いた本人 | 作成者 |
|---|---|---|---|---|---|
| グループの存在・名前・メンバー | ✕（404） | ○ | ○ | ○ | ○ |
| 中身（短冊） | ✕ | ✕（名乗るまで） | ○ | ○ | ○ |
| 下書きを読む | ✕ | ✕ | ✕ | ○ | ✕ |
| 編集・削除・公開の切替 | ✕ | ✕ | ✕ | ○ | ✕ |
| （削除すると、貼っていた写真も一緒に消える） | | | | | |
| メンバーを外す | ✕ | ✕ | ✕ | — | ○ |

無い slug には **404** を返す。ある slug には、名前とメンバーだけ見せて中身は見せない
（その URL が招待状なので、誰が居るところなのかは分からないと参加を判断できない）。

## 中身

- Next.js（App Router）+ Server Actions
- Prisma + PostgreSQL
- 名乗りは自前。クッキー一つと、それを控える表だけ（外部の認証は使っていない）
- 紙の質感は画像を使わず、SVG のノイズと繊維の重ね合わせ。
  **模様は開くたびに違う種から漉かれ、粒と斑がそれぞれ別の速さでゆっくり流れる。**
  動かすのは `transform` と `opacity` だけなので、描き直しは起きない
  （背景の位置を動かすと毎コマ描き直しになるので使っていない）。
  `prefers-reduced-motion` のときは止まる
- 音は音源ファイルを持たず Web Audio でその場で合成（右上の「音」で止まる）
- スタイルは `app/globals.css` 一枚。縦組みは `writing-mode: vertical-rl` と論理プロパティ
  （縦組みでは `inline` が上下、`block` が左右。仕切りの罫は `block` 側に引く）

### 写真の位置

**書く場では**、本文が前と後ろの二つに分かれ、そのあいだに写真そのものが置かれる。
目に見えているとおりに出るので、印を読み替える必要がない。

出るときは、**段落の一字下げに揃えて一字ぶん下げる**。縦組みでは `inline-start` が「上」なので、
そこに一字ぶんの余白を置いている。一字の幅は本文の字送りで決まるから、
写真の枠の `font-size` を本文に合わせてある（字下げのある段落にも無い段落にも、同じだけ下がる）。

**しまうときは**、本文の中の `［写真］` という印に畳んで一本の文字列に戻す。
構造を持つ編集器を作らずに済むし、印を持たない古い短冊もそのまま読める
（その場合は写真を本文より前に置く）。

### 写真の置き場

実体は **PostgreSQL の表**に入れている。Vercel はディスクに書けないし、
外の置き場を足すと環境変数が増える。この規模なら表に持つのが早い。

そのかわり二つ守っている。

- 貼った時点で**ブラウザ側で縮める**（長辺 1600px・JPEG）。
  スマホの一枚をそのまま送ると Server Action の上限にも回線にも重い。
- **Slip とは別の表**にしてある。同じ行に持つと、巻物を出すたびに
  全員分のバイト列を引くことになる。一覧では大きさだけを読む。

配信は `/i/[id]`。本文と同じ条件でしか返さず、見せてよくない人には 404。
`Cache-Control: private` に加えて **`Vary: Cookie`** を付けている。
これが無いと、名乗りを消したあとでもブラウザの控えから画像が返ってしまう。

```
lib/auth.ts        クッキーと名乗り（作る・なる・忘れる）
lib/photo.ts       貼られた一枚の受け取り（形式と大きさの確認）
lib/place.ts       未読の目印の位置
lib/guards.ts      グループと短冊の見せてよさ
lib/kanji.ts       日付を漢数字に
lib/sound.ts       紙の音の合成と、消音の状態
app/actions/       server actions（identity / places / slips）
components/        巻物の一枚・書く場・戸口・音まわり
```

## 公開する（Vercel）

GitHub に push すると Vercel が拾って公開しなおす。環境変数は二種類だけ。

| 名前 | どこから |
|---|---|
| `DATABASE_URL` / `DATABASE_URL_UNPOOLED` | Vercel の Storage で Neon を繋ぐと自動で入る |

環境変数はこれだけ。認証の鍵もメールの鍵も要らない。

`npm run build` が `prisma migrate deploy` を先に走らせるので、表の移行は公開のたびに当たる。

### 自動で公開されないとき

Vercel の無料プランは、**Git のコミット作者がアカウント所有者と結びつかない場合、
そのデプロイをブロックする**（GitHub 側に「Deployment was blocked」と出る。ビルドの失敗ではない）。
コミットの作者メールを、GitHub が自分だと認識するものにすれば直る:

```sh
git config user.email "<あなたのID>+<ユーザー名>@users.noreply.github.com"
```
