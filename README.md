# 交換日記

一冊のノートを、少人数で順番に回す。

> 交換日記（こうかんにっき）とは、日記の一種。複数、又は1冊の日記帳を友人間などで共有し、順番に回して日記をつけたり相手へのメッセージを書き込んでいく行為のこと、またはその共有される日記帳自体をいう。

この「またはその共有される日記帳自体をいう」に従って、**ノートそのものを主オブジェクトに置いている**。グループと記事の二階建てではなく、一冊のノートがそのまま人の集まりになる。

## 約束ごと

- ノートは、いつも**誰か一人の手元にしかない**。
- **持っている人だけが書ける。**
- 書いた頁は、**渡したときに封じられる**。封じられた頁はもう直せない。
- 読めるのは、**自分に回ってきたときに見えていたところまで**。手元にあるあいだは全部読める。
- 回ってきた新しい分の手前には、**栞**が挟まる。
- 入ったばかりの人には、まだ何も見えない。**ノートが回ってきて、はじめて読める。**

「公開」という操作はない。**渡す**という一手が、そのまま公開にあたる。

## OOUI

オブジェクトを選んでから、そのオブジェクトにできることを選ぶ。

| オブジェクト | コレクション | シングル | そこから生えるアクション |
|---|---|---|---|
| **ノート** | `/` 手元のノート一覧 | `/n/[slug]` 頁の連なり | 書く（手元にあるときだけ）・つくる |
| **頁** | ノートの中身そのもの | `/p/[id]` | 直す・消す（封じられる前だけ） |
| **仲間** | `/n/[slug]/nakama` | — | この人に渡す・外す |

- 「書く」は常設の釦ではなく、**ノートの末尾にある白紙そのもの**。手元にないときは現れない。
- 「渡す」は相手を選ぶ操作なので、**人を並べて、その人から渡す**。ウィザードにはしない。
- ノートの状態（誰が持っているか）は、見出しのすぐ下に常に出ている。

## 見た目

- ヘッダー以外はすべて縦書き（`writing-mode: vertical-rl`）。日付も漢数字（二〇二六年九月三日）。
- ノートは右から左へ繰る。**古い頁が右、新しい頁が左**。ひらくと、いちばん新しいところ（栞があれば栞）が目の前に来る。
- 書体は Google Fonts の Shippori Mincho B1。
- 紙の質感は画像を使わず、SVG のノイズと繊維の重ね合わせで漉いている。
- 音は音源ファイルを持たず、Web Audio でその場で合成する（頁をめくる音・筆が触れる音・墨を置く音・ノートを閉じて渡す音）。右上の「音」で止められる。

## 名乗り

**名前を入れるだけで始められる。** メールも外の名乗りも要らない。

その代わり、次に来るための **戻り口**（`/modoru/<長い文字列>`）を一度だけ渡す。
その URL を知っていることが、そのまま名乗りになる。控えそこねると戻れないので、
入った直後に大きく見せている。漏れたときは「作り直す」で前の URL を無効にできる。

ほかの入口も、鍵が入っていれば出る:

- **Google ではじめる** — `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` があるときだけ。
- **メールに届くリンク** — 本番では `RESEND_API_KEY` があるときだけ出す。
  無いのに出すと、送ったつもりで誰も入れない行き止まりになるため（開発中は端末に出るので常に出す）。

はじめてメールで来た人は、一度だけ「名を決める」画面を通る
（Google と名前だけの人は、その時点で名があるので通らない）。

### 気をつけること

公開 URL を知っていれば、誰でも名前を入れて名乗りを作れる。ただし**ノートの中身は
招待コードを知っている人しか見られない**ので、実質の鍵は招待コードのほう。
ログイン試行の回数制限はまだ入れていない。

## 動かす

```sh
brew install postgresql@17                                   # まだ無ければ
pg_ctl -D /opt/homebrew/var/postgresql@17 start              # 起こす
createdb kokan_nikki

npm install
cp .env.example .env        # DATABASE_URL と AUTH_SECRET を埋める（下記）
npx prisma migrate dev      # 表をつくる
npm run seed                # 手ざわりを見るための種データ（任意）
npm run dev
```

`AUTH_SECRET` は次で作れる:

```sh
node -e 'console.log(require("crypto").randomBytes(32).toString("base64url"))'
```

`http://localhost:3000` をひらく。

### 開発中のログイン

`/login` の下に「開発用」の貼り紙が出る。そこにいる人の釦を押せば、**メールを介さずそのまま入れる**。人を切り替えて回りを見るときは、これがいちばん早い。

本番ビルドでは、この貼り紙は出ないし、その処理も中身ごと消えて `throw` だけが残る（`NODE_ENV` で弾いている）。

メールのほうを通したいときは、**まだ実際には送っていない**ので、ログイン用のリンクが `npm run dev` を動かしている端末と `.mail/log.txt` に出る。そのリンクをブラウザに貼れば入れる。

種データを入れると、ノートが一巡したところから始まる:

| | |
|---|---|
| `hanako@example.com` | はなこ・つくった人・**いまノートを持っている** |
| `taro@example.com` | たろう・仲間 |

たろうが書いた頁が一枚、はなこにとって「新しく回ってきた分」になっているので、栞が挟まった状態が見られる。招待コードは `kmp4-t7xz`。種を蒔き直すには `npm run db:reset`。

### 実際にメールを送るようにする

`lib/mail.ts` の `deliver()` の中身だけを差し替える。Resend なら、その関数の中でこう呼ぶだけ:

```ts
await fetch("https://api.resend.com/emails", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.RESEND_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ from: FROM, to, subject: "交換日記へ", text: url }),
});
```

SMTP を使うなら `npm i nodemailer` して、`mailLink` を `next-auth/providers/nodemailer` の `Nodemailer({ server, from })` に置き換える。

### Google ではじめる を使えるようにする

1. Google Cloud で「OAuth クライアント ID（ウェブ アプリケーション）」をつくる。
2. 承認済みのリダイレクト URI に、使う場所のぶんだけ入れる:
   - `http://localhost:3000/api/auth/callback/google`
   - `https://<公開したドメイン>/api/auth/callback/google`
3. `AUTH_GOOGLE_ID` と `AUTH_GOOGLE_SECRET` を入れて、立て直す。

鍵が入っていないうちは、その釦は出ない（メールだけで動く）。

**名乗りの結びつけについて。** 同じメールアドレスなら、メールのリンクで作った名乗りと
Google の名乗りは同じ人として扱う（`allowDangerousEmailAccountLinking`）。
これを入れないと、先にメールで入った人が Google で入り直せなくなるため。
結びつける以上、`signIn` コールバックで **Google 側が確認済みのアドレスかどうか
（`email_verified`）を必ず見ている**。未確認のまま通すと、他人の名乗りに入り込めてしまう。

## 権限

| | ノートの外の人 | 仲間（持っていない） | 仲間（持っている） | 書いた本人 | つくった人 |
|---|---|---|---|---|---|
| ノートを見る | ✕（404） | ○ | ○ | ○ | ○ |
| 封じられた頁を読む | ✕ | 自分が見たところまで | 全部 | — | — |
| 封じる前の頁を読む | ✕ | ✕ | ○（自分の分） | ○ | ✕ |
| 書く | ✕ | ✕ | ○ | — | — |
| 直す・消す | ✕ | ✕ | — | ○（封じる前だけ） | ✕ |
| 渡す | ✕ | ✕ | ○ | — | — |
| 招待コードの作り直し・除名 | ✕ | ✕ | — | — | ○ |

見せてはいけないものは、403 ではなく 404 を返す。ノートや頁の存在そのものを伏せるため。
ノートを持っている人は外せないし、持ったままでは抜けられない（回りが止まるので）。

## 中身

- Next.js（App Router）+ Server Actions
- Prisma + SQLite
- 名乗りは Auth.js（NextAuth v5）。セッションは DB の表で持つ
- スタイルは `app/globals.css` 一枚。縦組みは `writing-mode: vertical-rl` と論理プロパティで組んでいる
  （縦組みでは `inline` が上下、`block` が左右になる。仕切りの罫は `block` 側に引く）

```
auth.ts            Auth.js の設定（Google と、メールのリンク）
lib/mail.ts        ログイン用リンクの届け方。ここだけ差し替えれば実送信になる
lib/auth.ts        いま名乗っている人を取り出す・名乗りを求める
lib/notebook.ts    回す約束ごと（次の番・栞の位置・読んでよい範囲）
lib/guards.ts      ノートと頁の見せてよさの判定
lib/kanji.ts       日付を漢数字に
lib/sound.ts       紙の音の合成と、消音の状態
app/actions/       server actions（auth / notebooks / pages）
components/        見出し・書く場・渡す・戸口・音まわり
```

## 公開する（Vercel）

GitHub に push すると、Vercel が拾って自動で公開しなおす。

必要な環境変数は二種類だけ:

| 名前 | どこから |
|---|---|
| `DATABASE_URL` / `DATABASE_URL_UNPOOLED` | Vercel の Storage で Neon（Postgres）を繋ぐと、自動で入る |
| `AUTH_SECRET` | 自分で作って入れる（上のコマンド） |

`npm run build` が `prisma migrate deploy` を先に走らせるので、**表の移行は公開のたびに自動で当たる**。

### 自動で公開されないとき

Vercel の無料プランは、**Git のコミット作者がアカウント所有者と結びつかない場合、
そのデプロイをブロックする**（GitHub 側に「Deployment was blocked」と出る。
ビルドの失敗ではない）。手動の Redeploy は通るのに push からだけ動かない、
という形で現れる。

コミットの作者メールを、GitHub が自分だと認識するものにすれば直る:

```sh
git config user.email "<あなたのID>+<ユーザー名>@users.noreply.github.com"
```

いま結びついているかは、これで見られる（`結びついていない` なら、それが原因）:

```sh
gh api repos/<ユーザー名>/<リポジトリ>/commits/main --jq '.author.login // "結びついていない"'
```

Google ではじめる を本番でも使うなら、承認済みのリダイレクト URI に
`https://<公開したドメイン>/api/auth/callback/google` を足して、`AUTH_GOOGLE_ID` /
`AUTH_GOOGLE_SECRET` を Vercel 側にも入れる。

### メールについて

`RESEND_API_KEY` を入れないかぎり、ログイン用のリンクは**サーバーのログに出るだけ**で、
実際には送られない。つまり自分以外は入れない。人を招くなら Resend の鍵を入れること。
