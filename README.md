# 短冊

仲間うちだけで、縦書きで、本音や雑記を書き散らせる場所。

- **返事はいらない。** 誰かに宛てて書くのでも、応えるのでもない。
- **順番も手番もない。** 誰でも、いつでも書ける。
- **整っていなくていい。** エッセイである必要も、日記である必要もない。
- **いいね・既読・閲覧数・フォロワー数は、一つも作らない。** 数えないことが、この場の性格そのもの。
- **日記ほど私的すぎず、SNSほど公的すぎない。** 濃い文脈が共有されている前提で書ける。
- **縦書きで「読む」。** タイムラインを眺めるのではなく、文章を読む。

書く画面では **⌘（Windows は Ctrl）+ Enter** で投稿できる。
変換中は決して送らない（Enter は変換の確定にも使うので）。

## 巻物

グループを開くと、全員の短冊が**全文のまま、右から左へ連なっている**。
開いた瞬間に、もう誰かの文章を読んでいる状態になる。

**並びは古いものから新しいものへ。** 縦組みでは、それが右から左へ流れる向きになる。
一枚の中で後の文字ほど左にあるのと、向きが揃う（巻物も右端から書き始める）。
最新を右端に置くと、縮尺を変えたときに時間が逆流するうえ、
新着を読むとき必ず逆時系列になってしまう。

「開いてすぐ新着に届く」は、並びではなく**着地点**で引き受ける。
前に見たあとに書かれた分があれば、その目印の位置に立つ。
なければいちばん新しいところ（左端）へ。はじめて来た人は、はじめから。

- カードも、抜粋も、「続きを読む」もない。**走り読みという行為が成立しないようにしてある。**
- **投稿と投稿のあいだに罫は引かない。** 段落は日本語の縦組みどおり「一字下げ＋改行」だけで
  詰めてあるので、そのぶん余る空きが、そのまま投稿の切れ目として働く。
  仕切っているのは、書いた人の名前と、空きだけ。
- 本文はリンクではない。読むもの、引用するものなので。
- リンクなのは**書いた人の名前**（その人の分だけを続けて読む）と**日付**（その一枚だけを開く）。
- 前に見たあとに書かれた分の手前に、細い朱の目印が入る。**未読の「数」はどこにも出さない。**
  数が出た時点で、消化すべきものになってしまうので。

## 言葉づかい

機能の名前は、ウェブで通じている言葉をそのまま使う（投稿・下書き・公開・編集・削除・メンバー・ログアウト）。
雰囲気は、本文と佇まいの側で出す。

例外は**合言葉**。グループに入るための符牒で、作った人が決める。
`kmp4-t7xz` のような羅列ではなく、口で言って渡せる言葉にしておける。

## 動かす

```sh
brew install postgresql@17                                   # まだ無ければ
pg_ctl -D /opt/homebrew/var/postgresql@17 start              # 起こす
createdb kokan_nikki

npm install
cp .env.example .env        # DATABASE_URL を埋める
npx prisma migrate dev
npm run seed                # 手ざわりを見るための種データ（任意）
npm run dev
```

### 開発中の人の切り替え

入口の下に「開発用」の貼り紙が出る。人の釦を押せばその人として見られる。
本番ビルドでは出ないし、その処理も中身ごと消えて `throw` だけが残る。

種データを入れると、はなこで見たときに未読の目印が出る状態から始まる。
グループ「三人のところ」の合言葉は `ゆうやけ`。

## 名乗り

**アカウントはない。** 調整さんや walica と同じで、登録もログインもない。

- はじめて来た人は、**名前をひとつきかれるだけ**。それで始まる。
- 名前は**ブラウザのクッキー**に紐づく。サーバー側には名前しか持たない。
- 誰かを誘うときは、**グループの URL をそのまま渡す**。開いた人は名前を入れて、そのまま仲間になる。
- 口頭で渡したいときのために、**合言葉**からも入れる。

### クッキーを失ったら

グループの URL をひらくと、メンバーの名前が並ぶ。そこから自分を選び直せば戻れる。

**つまり、URL を持っている人は誰にでもなりすませる。** 照合するものが何もないので、
これは防げないし、防ごうとしていない。守っているのは「その URL を知っているのは
仲間だけ」という一点だけ。仲間うちで使う前提の割り切り。

せめて、すでに名乗っている人にはこの選び直しを出さない（まだ誰でもない人の戻り道に留める）。

## 画面

| 道筋 | なに |
|---|---|
| `/` | はじめての人には名前をきく。名乗っていればグループの一覧 |
| `/new` | グループを作る |
| `/me` | 名前を変える・このブラウザから消す |
| `/b/[slug]` | 巻物。**この URL が招待状**。まだ仲間でない人には名前をきく |
| `/b/[slug]/write` | 書く |
| `/b/[slug]/by/[userId]` | その人の分だけを続けて読む |
| `/b/[slug]/members` | メンバー・招待 URL・合言葉 |
| `/s/[id]` | 一枚だけを開く |
| `/s/[id]/edit` | 編集 |

## 見えかた

| | URL を知らない人 | URL を知っている人 | メンバー | 書いた本人 | 作成者 |
|---|---|---|---|---|---|
| グループの存在・名前・メンバー | ✕（404） | ○ | ○ | ○ | ○ |
| 中身（短冊） | ✕ | ✕（名乗るまで） | ○ | ○ | ○ |
| 下書きを読む | ✕ | ✕ | ✕ | ○ | ✕ |
| 編集・削除・公開の切替 | ✕ | ✕ | ✕ | ○ | ✕ |
| 合言葉の変更・メンバーを外す | ✕ | ✕ | ✕ | — | ○ |

無い slug には **404** を返す。ある slug には、名前とメンバーだけ見せて中身は見せない
（その URL が招待状なので、誰が居るところなのかは分からないと参加を判断できない）。

## 中身

- Next.js（App Router）+ Server Actions
- Prisma + PostgreSQL
- 名乗りは自前。クッキー一つと、それを控える表だけ（外部の認証は使っていない）
- 紙の質感は画像を使わず、SVG のノイズと繊維の重ね合わせ
- 音は音源ファイルを持たず Web Audio でその場で合成（右上の「音」で止まる）
- スタイルは `app/globals.css` 一枚。縦組みは `writing-mode: vertical-rl` と論理プロパティ
  （縦組みでは `inline` が上下、`block` が左右。仕切りの罫は `block` 側に引く）

```
lib/auth.ts        クッキーと名乗り（作る・なる・忘れる）
lib/place.ts       未読の目印の位置
lib/guards.ts      グループと短冊の見せてよさ
lib/kanji.ts       日付を漢数字に
lib/sound.ts       紙の音の合成と、消音の状態
app/actions/       server actions（identity / places / slips）
components/        巻物の一枚・書く場・戸口・音まわり
```

## 公開する（Vercel）

GitHub に push すると Vercel が拾って公開しなおす。環境変数は二種類だけ。

| 名前 | どこから |
|---|---|
| `DATABASE_URL` / `DATABASE_URL_UNPOOLED` | Vercel の Storage で Neon を繋ぐと自動で入る |

環境変数はこれだけ。認証の鍵もメールの鍵も要らない。

`npm run build` が `prisma migrate deploy` を先に走らせるので、表の移行は公開のたびに当たる。

### 自動で公開されないとき

Vercel の無料プランは、**Git のコミット作者がアカウント所有者と結びつかない場合、
そのデプロイをブロックする**（GitHub 側に「Deployment was blocked」と出る。ビルドの失敗ではない）。
コミットの作者メールを、GitHub が自分だと認識するものにすれば直る:

```sh
git config user.email "<あなたのID>+<ユーザー名>@users.noreply.github.com"
```
